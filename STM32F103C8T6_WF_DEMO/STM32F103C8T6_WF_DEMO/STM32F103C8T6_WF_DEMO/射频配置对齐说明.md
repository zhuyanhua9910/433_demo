# 射频配置与参考 demo 对齐说明

> 参考：`433-2k-20k/DemoCode`（QX4463 + STM32F103RC，双向包模式）
> 本工程：`STM32F103C8T6_WF_DEMO`（Wf4463 + STM32F103C8T6）
> 日期：2026-11-16

## 1 结论

可行。射频层已按参考 demo 的「双向包」配置对齐：**433.920 MHz / 10 kbps / 2FSK / ±20 kHz 频偏 / 8 字节前导 / 0xB42B 同步字 / 固定 7 字节载荷 / CRC-16 IBM**。

包结构由原来的「1 字节长度头 + 变长载荷」改为「固定 7 字节」，与 demo 的 `PKT_FIELD_1_LENGTH = 7` 对齐，两端可以互收。

## 2 已修改项

### 2.1 `Core/Wf4464/Inc/radio_config.h`

| 属性 | 原值 | 新值 | 说明 |
|---|---|---|---|
| `RF_FREQ_CONTROL_INTE_8` 的 FRAC | `0x0D 0xDD 0xDD` | `0x0E 0xD9 0x16` | 433.000 → **433.920 MHz**（INTE 仍是 0x38） |
| `RF_PKT_CRC_CONFIG_7` 的 `PKT_CRC_CONFIG` | `0x84` | `0x04` | 多项式都是 4 = CRC-16 IBM，仅 bit7 差异，跟随 demo |
| `RF_PKT_LEN_12` 的 `PKT_LEN` | `0x22` | `0x00` | 关闭长度字段解析（变长 → 固定） |
| `PKT_LEN_FIELD_SOURCE` | `0x01` | `0x00` | 无长度字段来源 |
| `PKT_FIELD_1_LENGTH` | `0x0001` | `0x0007` | 字段 1 由「长度头」变成 7 字节载荷 |
| `PKT_FIELD_1_CRC_CONFIG` | `0x80` | `0xAA` | 与 demo 一致 |
| `PKT_FIELD_2_LENGTH` | `0x1FFF` | `0x0000` | 变长字段停用 |
| `PKT_FIELD_2_CONFIG` | `0x00` | `0x00` | 不变 |

`RADIO_CONFIGURATION_DATA_RADIO_PACKET_LENGTH` 原本就是 `0x07`，未变。

### 2.2 `Core/Wf4464/Src/wf4463_app.c`

- `wf4463_tx()`：去掉「FIFO 首字节写长度」和「每次改 `PKT_FIELD_2_LENGTH`」；改为把载荷直接放进 FIFO，**不足 7 字节尾部补 0x00**，固定写 7 字节。长度上限由 `WF4463_MAX_PAYLOAD`(63) 收紧到 7。
- 新增 `WF4463_FIXED_PKT_LEN`，取自 `RADIO_CONFIGURATION_DATA_RADIO_PACKET_LENGTH`，与配置联动。
- `wf4463_rx_start()`：删掉「恢复 `PKT_FIELD_2_LENGTH` 为 0x1FFF」的调用（固定包长下不需要）。
- `wf4463_rx_fetch()`：逻辑不变（FIFO 里就是 7 字节纯载荷），仅更新注释。

### 2.3 `Core/Src/main.c`

| 项 | 原值 | 新值 |
|---|---|---|
| `APP_PACKET_LEN` | 12 | **7** |
| 载荷格式 | `"WF HELLO %03u"`（12 字节） | **`"WF%05u"`**（7 字节，如 `WF00001`） |

### 2.4 注释同步

`wf4463_app.h`、`wf4463_port.h` 中把「变长包 / 长度字节」的描述改为固定包长。

## 3 未跟随 demo 的项（有意保留）

| 属性 | 本工程 | demo | 保留原因 |
|---|---|---|---|
| `GLOBAL_XO_TUNE` | **0x52** | 0x66 | 晶振负载电容校准值，由本板晶振决定。照抄会让频点偏移 |
| `PA_TC` | **0x3D** | 0x1D | PA 上升沿时间，与本板 PA 匹配相关；不影响互通 |
| `INT_CTL_ENABLE` / `INT_CTL_PH_ENABLE` | 0x07 / 0x3B | 0x01 / 0x38 | 本工程 `rx_fetch()` 依赖前导/同步中断，且走 MODEM 中断；改为 demo 值会削弱现有判据 |
| `GLOBAL_CONFIG` | 0x60 | 0x20 | 本模块无外部 RF 开关（裸模块），GPIO 行为不同 |
| `PKT_WHT_*` | 0x00/0x30/0x00 | 0x01/0x08/0x20 | `PKT_CONFIG1 = 0x02` 未启用白化，这些值不生效 |
| `MODEM_AFC_WAIT` / `AGC_CONTROL` 等 | 略有不同 | — | WDS 版本(3.2.8 vs 3.2.11)与选项差异导致的接收机调优值，不影响同频解调 |

## 4 烧录后验证步骤

1. **自检（两块本板）**
   - 串口应看到 `TX #n > WF000xx`，另一块 `RX #n < "WF000xx" | len=7`。
   - 启动日志里 `DIAG ... xo=0x52` 说明配置写入成功。

2. **与参考 demo 互通**
   - demo 板上电后按 **PD2** 切到第三档，屏幕显示 `< BidirectionalPkt >`。
   - demo 按 **PC10** 发 `"BUTTON1"` → 本工程接收端串口应打印 `RX #n < "BUTTON1" | len=7`。
   - 本工程发送端发 `WF000xx` → demo 屏第 5 行显示该字符串（demo 只认 `"BUTTON1"`，不会回 ACK）。

3. **想触发 demo 的 ACK 握手**
   - 临时把 `main.c` 的载荷改成 7 字节 `"BUTTON1"`，demo 收到后会回 3 字节 `"ACK"`，本工程串口打印 `RX #n < "ACK"`。

## 5 已知限制

- demo 的 ACK 是 **3 字节**，且收完数据后立刻 `StartRx(期望长度 7)`。本工程固定 7 字节无法回 3 字节 ACK，因此**只能单向互通**（收发数据都行，但 demo 那套「数据+ACK」完整握手跑不通）。
- 若要完整双向握手，需要把 demo 的 `AckPacket` 长度与 `Radio_StartRx()` 的期望长度一起改成 7，或本工程改回变长包。
- 修改前的文件已备份为同目录下 `*.bak`（`radio_config.h.bak`、`wf4463_app.c.bak`、`main.c.bak`）。
